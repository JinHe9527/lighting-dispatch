## 已完成的结构性修复

- 工单状态统一为 `pending → assigned → in_progress → completed`，另有 `cancelled` 和 `abnormal`；未来排期不再改变人员当前状态。
- 所有指派入口统一检查组别、账号审批、实习身份、离岗（请假/出差）、完整班次区间和时间重叠。
- 团队账号绑定 `team_id`，只能提交和查看本团队工单，不能指定工作人员，也不能读取人员和个人统计。
- 团队预约默认限制为未来 7 天、最多 2 个未开始预约、每天 240 分钟；检查与写入位于同一 SQLite 写事务。
- 任务规则的工时是下单默认值；每单可以明确填写 10–720 分钟预计时长，预约按本次时长占用连续区间。超过 240 分钟必须进入独立审核，不能拆单或伪造参数绕过。
- 自动派单按当日分钟、未来 7 天分钟、当日单量、上次派单时间轮转，避免固定偏向某位工作人员。
- 开始任务受提前窗口限制；未开始不能完成；完成说明、工作会话和订单事件在同一事务中保存。
- 转包保持原负责人责任直到新负责人接受；第二次及以后、两小时内、进行中或同单再次交接需要组长审批；历史负责人不能来回接回同一订单。
- 进行中或 15 分钟内开始的转包在发起与接受时都会复检接手人的实时状态；小休、下班、巡检或忙碌人员不能接手正在发生的任务。
- 人员有进行中或即将开始的工单时只能保持忙碌；后台不能把他改成巡检、下班或空状态，“结束小休”明确恢复为空闲。
- 仍有未结束工单的任务规则禁止改名或换组；班次修改如果会让现有已派工单超出班次范围则拒绝保存。
- 取消和异常终止不再物理删除订单；进行中订单只能由管理员异常终止，统计不会把异常伪装成完成。
- 附件使用一次性 token 认领，下载按订单可见范围鉴权；上传前先保留容量，单账号最多 6 个未使用附件、合计 180MB，并强制预留 512MB 磁盘空间。中断上传 1 小时、未认领附件 24 小时后回收。
- 审计仅管理员可读且不可清空；人员、规则、班次、删除、设置和管理员认领均在业务写事务提交前写入审计。
- 飞书消息和任务进入持久 outbox，失败指数退避并最多重试 5 次；`sending` 在重启或超时后自动恢复。消息、加急、任务创建和成员绑定分别记录进度，重试不会从第一步重复执行。
- 未登录请求按可信客户端 IP 限流，已登录请求按已验证的用户 ID 限流；伪造或轮换无效 `sid` 不能绕过登录接口限流。
- 后台线程独立执行预约释放、超时提醒、异常升级、转包超时、附件清理、会话清理和数据库备份，不再依赖有人打开页面。
- 服务限制并发线程和连接超时；本地图标替代第三方 CDN；增加 CSP、安全响应头、HTTPS Secure Cookie 和 HSTS。
- CSV 导出阻止公式注入；正式环境禁止清空业务数据；配置删除前检查引用关系。
- 所有弹窗统一为真正的 `dialog`：支持 `Esc` 关闭、焦点限制、关闭后焦点恢复和背景滚动锁定；所有图标按钮、动态表单与统计行补齐可访问名称、标签和键盘操作。
- 页面导航同步到 URL，刷新与浏览器前进/后退可以恢复当前页面；下单草稿存在时，页面切换、返回和关闭浏览器都会先确认，后台轮询不会覆盖填写中的内容。
- 移动端允许双指缩放；导航、筛选、表单、配置操作、排班格和图标按钮均达到可靠触控尺寸，窄屏页面没有文档级横向溢出。
- Linux 发布改为只读版本目录和原子 `current` 链接切换；代码由 `root` 持有，运行用户只能写 `/var/lib/wuyou-dispatch` 与 `/var/backups/wuyou-dispatch`。首次从旧目录升级会先停服务并通过 SQLite backup API 迁移数据；如果目标目录已有空库，会先备份空库再恢复旧库。健康检查失败会恢复部署前的程序链接和服务配置。
- 数据、媒体、日志和代码目录已经分离；每日备份包含 SQLite 快照和不可变媒体副本，配置文件由 `root` 单独备份。设置 `DISPATCH_BACKUP_MIRROR_DIR` 后可同步到挂载的异盘或远端备份目录。
