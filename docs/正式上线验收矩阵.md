# 正式上线验收矩阵

本文把已经确认的需求按角色、输入、处理、状态、输出和上下游影响整理为唯一验收清单。代码、测试、正式环境三者必须一致；任一项不一致即不算完成。

## 角色能力

| 能力 | 团队下单方 | 普通工作人员 | 本组组长 | 管理员 | 管理层只读 |
|---|---:|---:|---:|---:|---:|
| 查看数据 | 仅绑定团队 | 本组待派、本人负责或创建 | 本组全部 | 全部 | 与管理员相同 |
| 创建工单 | 绑定团队 | 本组且固定本人 | 本组，可指定本组人员 | 全部，可指定对应组人员 | 否 |
| 接单 | 否 | 本组可接单 | 本组可接单 | 可管理指派 | 否 |
| 审核超 4 小时任务 | 否 | 否 | 本组，不能绕过人员资格 | 全部，不能绕过人员资格 | 否 |
| 开始、完成 | 否 | 仅本人责任工单 | 自己负责时同普通工作人员 | 自己负责时同普通工作人员 | 否 |
| 改派、异常终止 | 否 | 走转包交接 | 本组 | 全部 | 否 |
| 调整排班与离岗 | 否 | 否 | 本组其他成员 | 其他成员 | 否 |
| 账号身份与团队绑定 | 否 | 否 | 否 | 是 | 否 |
| 全局规则与本职直播间 | 否 | 否 | 查看本组结果 | 编辑 | 否 |

## 全链路业务验收

### 1. 账号准入与身份绑定

- 输入：飞书登录账号、使用身份、所属分组或绑定团队、准入与停用状态。
- 处理：团队身份必须绑定一个真实团队；工作人员身份必须属于一个真实分组；身份切换在单次事务内清理不适用字段。
- 状态：未授权或已停用账号不能调用业务接口；管理层只读可以看管理数据但所有写接口返回拒绝。
- 输出：各角色只看到自己权限范围内的导航、人员、工单、统计和附件。
- 上下游：停用账号立即撤销会话；本职负责人失去工作人员资格时自动清除长期绑定。

### 2. 下单与任务描述

- 输入：处理组、直播间/团队、任务、预计时长、立即或预约、负责人（仅管理者）、备注及附件。
- 处理：任务可从规则库选择，也可填写 2–80 个字的自定义任务；预计时长为 10–720 分钟，规则库工时只作为默认值。
- 状态：普通工作人员创建后固定指派本人；团队下单方不能指定人员；组长和管理员可直接指派符合条件的本组人员。
- 输出：下单前明确显示任务、开始、预计结束、总时长、负责人和是否需要审核。
- 上下游：班次、离岗、账号资格、实习身份、时间冲突和即时状态由服务端统一检查。

### 3. 立即、预约与远期安排

- 输入：今天、明天、后天或日期选择器中的任意允许日期。
- 处理：未来日期只能预约，界面不显示“立即”，服务端也拒绝过去时间；预约按本次预计时长占用连续时间段。
- 状态：未来任务不改变人员当前空闲或忙碌状态。
- 输出：日视图同时显示今天、明天、后天；周、月视图可定位远期任务并进入当天小时排班。
- 上下游：团队账号受未来天数、未开始预约数量和普通预约日上限约束。

### 4. 超长任务审核

- 输入：单次预计时长超过 240 分钟的普通团队或工作人员工单。
- 处理：创建为`待派工 + 超长任务待审核`，保存原定负责人但不正式指派；审核时再次检查负责人资格、班次、离岗和冲突。
- 状态：审核前不能接单、指派或开始；通过后进入待派工或已派待开始；驳回后保留历史并进入已取消。
- 输出：下单页、调度页和工单详情均明确显示“待审核”；可接工单页不混入不可接的审核单。
- 上下游：组长只审核本组，管理员审核全部；管理者亲自创建超长任务视为已完成本次业务审核。

### 5. 本职灯光师与人工指派

- 输入：直播间的长期本职灯光师设置。
- 处理：自动派单和默认推荐先检查本职灯光师；不可派时进入本组公平分配，不因长期关系卡死工单。
- 状态：本职关系只影响优先级，不形成排他权限；管理员和组长可把任何直播间指派给任意符合条件的本组成员。
- 输出：人员页显示每人负责范围，直播间设置显示当前负责人，下单选择器把本职负责人排在首位并标注。

### 6. 执行、结束与时间核实

- 输入：负责人点击开始；结束时填写实际结束时间和完成说明。
- 处理：只能开始本人已指派任务，且受提前开始窗口、即时状态和并发任务检查；提前或补报结束进入独立时间核实。
- 状态：`已派待开始 → 进行中 → 结束核实 → 已完成`；核实期间继续占用负责人，避免重复派单。
- 输出：工作人员端持续显示当前任务、计时、直播间和任务内容；团队端能看进度并对结束时间提出异议。
- 上下游：工作会话驱动实际工时统计；异常终止和时间修正均保留事件与审计。

### 7. 转包与责任交接

- 输入：负责人选择原因，可指定接手人或开放给本组。
- 处理：发起和接受两个时点都复检接手人；紧急、重复、进行中或同单再次交接需要独立管理者审批。
- 状态：新负责人接受前原负责人不释放；接受后原子切换负责人和进行中的工作会话。
- 输出：发起人、接手人和管理者收到对应通知；不能自审或把订单转回历史负责人。
- 上下游：超时只升级提醒，不自动取消或制造无人负责状态。

### 8. 排班总览与时间轴

- 输入：分组、日/周/月视图、任意日期、人员和时间点。
- 处理：班次只是可用范围，真实任务单独渲染；取消和异常不作为有效安排；时间轴按 30 分钟及更短任务保持可识别。
- 状态：当前时间线只在今天出现并贯穿所有人员行；鼠标或触摸点位显示对应时间。
- 输出：一眼看到谁可派、谁在几号直播间、任务落在哪个时间段；短任务只显示直播间数字，不用大按钮遮挡时间轴。
- 上下游：点击空白时间直接带入人员、日期和时间创建任务；点击任务打开同一工单详情。

### 9. 飞书同步

- 输入：订单创建及其后续任何版本变化。
- 处理：数据库触发器把日历同步写入持久 outbox；后台创建或更新同一共享日历事件，失败按阶段重试。
- 状态：待派、已派、进行中、结束核实和完成均保留日历事件；取消或异常移除事件。
- 输出：飞书共享日历显示直播间、团队、任务、负责人、状态和完整起止时间。
- 上下游：个人飞书任务仅负责已指派人员的到岗提醒，与全局共享日历独立。

### 10. 配置持久化与删除

- 输入：账号绑定、团队、本职负责人、任务默认工时、班次、分组和规则变更。
- 处理：仍被活动工单引用的任务或班次禁止破坏性修改；删除任务后不再由启动种子重新创建。
- 状态：正式环境禁止清空业务订单和审计；取消业务必须改状态，不物理删除历史。
- 输出：页面刷新、服务重启和发布后配置保持一致。
- 上下游：所有配置写入同一正式数据库并记录审计，不随代码发布包覆盖。

## UI 验收

- 桌面与 320px 手机端无文档级横向溢出；触控目标不小于 44px，允许双指缩放。
- 分组切换、通知、刷新和头像在手机端同一顶部区域，不额外浪费一排高度。
- 手机主导航固定四个高频入口，其余功能从“更多”进入；每个角色只显示有权限的入口。
- 所有图标来自图标库，不使用 Emoji；图标按钮有可访问名称，表单有标签，键盘焦点清晰。
- 弹窗支持 `Esc`、焦点限制、关闭后焦点恢复和背景滚动锁定；下单草稿离开前提示。
- 调度卡片保持单行信息层级：到岗时间、团队/直播间、任务、负责人、状态、详情，不用大圆形详情按钮占位。
- 从人员时间轴打开派单时，该人员负责的直播间置于选项最前并默认第一项；上一次下单选择不得覆盖本职优先级。
